Theming

One layout, a theme per product

Components only ever ask for a role: ink, line, accent, short. Each product answers those roles in its own file. A retail workspace answers them as Tender, a school as Campus, and the screens do not change.

How the workspace picks it

  1. 1The workspace's profile is its primary product: RETAIL is Tender, SCHOOLS is Campus.
  2. 2The root layout reads it on the server and sets data-product and data-theme on the page, so the first paint is already right.
  3. 3One CSS file per product sets every role. A typed list of the role names means a product cannot leave one out.
  4. 4Tailwind's theme maps its utilities onto the same roles, so a class like bg-surface follows the product without knowing which one it is.

What Tender brings

  • Orange, not tomato, in the interface: #E8620F reads as orange where the mark's tomato reads red on a screen. It is spent once per screen, on the primary action, plus the focus ring and the ticks. Selection, active filters and grouping stay in warm neutrals.
  • The button is a deeper orange, #B84A0C, so its white label reads at 5.2:1. The brighter orange is kept for the focus ring and ticks, which only need 3:1.
  • Warm ink, never black. Dark mode takes the greys to warm near-black and keeps the mark, marigold and EcoCash blue as they are.
  • Danger moves to crimson, so a short drawer never reads as a button.
  • Money is written the way the till prints it: US$886.85.
  • The isometric drawings are for empty states and first runs, in their light or dark export to match.
