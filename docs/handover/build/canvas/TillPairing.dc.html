W-04 · W-76 · Tills and devices

One app, any device, one till each

A till is a place money is taken: a drawer, its float, its shifts and its Z report. A device is what runs Tender at it. Pairing ties one device to one till, so the device always knows where it is and the cashier only has to say who they are.

CounterMiniThe counter unit: a tablet for the cashier, a phone facing the customer, printer and drawer in one housing. Tender opens when it powers on and stays full screen.Pairs as one till, with its drawer and printer.
KoraThe handheld: a phone in a scanner sled, an optional belt printer, a dock. For queues, the cold room and the delivery bay.Pairs as its own till. Card and EcoCash, and cash only when it carries a float.
A browserAny laptop, PC or tablet on the shop’s POS address, in a tab or installed as an app. The scanner types like a keyboard; receipts go through the print dialog.Pairs as a till like the others. Nothing about the screens changes.
The same views everywhere. CounterMini and Kora run the POS portal too, inside a kiosk shell that opens it full screen and drives the printer, drawer and customer screen. So there is no tablet app and browser app to keep in step: the question is never which app, only which till this device is.

1 · On the device

Not paired: it asks for a code

Any device that opens Tender without a pairing shows this, and nothing to sell with. Nobody signs in to pair: the code is the proof that a manager said yes, so no manager password is ever typed on a shop-floor device.

Kora reads the code’s QR with its scanner; CounterMini and a browser take the six digits.

2 · In the back office

A manager makes the code

Pair a till makes a new till and its code in one go. On an existing till, Pair another device does the same for a replacement. Only owners and managers see either.

The code is six random digits, stored only as a hash, good once and for 10 minutes. Five wrong tries on a device stop it for 15 minutes.

3 · On the device

Paired: the till is known, people unlock it

Pairing gives the device its own key: a long random secret in a cookie the page’s scripts cannot read, sent only to the POS address. The server keeps a hash of it and a row for the device: its till, what it is, who paired it, when it was last seen.

Every request then carries two things. The key says which till; the PIN or sign-in says who. A shift opens on this till with no picker, and every sale, offline ones included, carries the till and the device.

4 · Both

Unpaired, replaced or lost

Unpair from the till’s page once its shift is closed. Pairing a replacement unpairs the old device in the same step. For a lost device, unpair it and close its shift from the shift itself, with the count.

The key stops working at the device’s next request. Sales it held offline still come in, because they happened, and are flagged for a manager to look at.
