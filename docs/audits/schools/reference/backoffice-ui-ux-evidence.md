Raw screen-level findings, rule digest, and screenshot observations behind the admin, head and bursar UI/UX documents. Line numbers are as of 2026-09-14 on `main`.


Scope: `app/schools/**`, `app/management/master-data/schools/**`, `components/schools/**` (portals excluded), sidebar config in `lib/navigation.ts` / `lib/workspaces.ts`, grants in `lib/schools/access.ts` / `lib/platform/personas.ts`. ## 0. Rules digest — the testable checklist

Drawn from `docs/ux/platform-ux-playbook.md` (canonical, wins conflicts), `docs/design-system/{README,05-rules,08-cookbook-patterns,12-tables}.md`, the campus-specific `09-campus-canvas-law.md`, `10-campus-screen-contract.md`, `11-campus-states-and-motion.md`, `.impeccable.md`, and `SPEC.md`.

**Naming and chrome (canvas law §1–4, playbook "Shell patterns")**
- R1. A page is named **once**, in the top app bar via `PageChrome`. No in-page `PageHeader`/`PageHeading` (spends ~110px of an 844px phone, and the bar already says it).
- R2. The band under the bar carries **state chips** (`{label, value, tone}`), never the page's name and never a caption explaining a word. Where nothing changes, there is no caption.
- R3. **One primary action per surface**, brand-filled, in the app bar. No action duplicated across header + toolbar + row.
- R4. Tabs, contextual search and filters sit in **one row directly above the table** (`TableControls`); controls share one height; filters never split between band and card. **One search box per screen.**
- R5. Row verbs in the row via `RecordActions` — `layout="menu"` inside a table. Bulk verbs in a floating bottom bar that appears only on selection, with count + clear.
- R6. **One table per active view**; multi-table contexts use vertical tabs / a view switcher; only the active panel renders a table.
- R7. Record lists look like `/crm/companies`: identity in the first column (only it is clickable), `RecordCell` tones, em-dash never blank, figures right-aligned, below `md` the table becomes the module's row list (`mobile` / `mobileListRenderer`).

**Copy and vocabulary (05-rules, canvas law §"Copy")**
- R8. Sentence case everywhere; no ALL CAPS, no Title Case labels.
- R9. Empty state = what, why, next action. Three empties are three sentences: `NothingYet` (offers the verb), `NothingMatched` (names filters, offers clear, never a create button), `NothingLeftToDo` (good news, no create).
- R10. Destructive actions name the object; confirm dialog states outcome + consequence, not "Are you sure?"; reasons are typed where the endpoint needs them.
- R11. Canonical status vocabulary — the DS five (Needs input / Running / Completed / Idle / Not started) or the playbook seven. Domain states are tolerated only if used consistently and never synonym-drifted.
- R12. Strip explanatory text: no subtitles restating the title, no rationale paragraphs, no `FieldHelp` noise (SPEC §"Remove cognitive overload").

**Values (05-rules "Value formatting", canvas law §6)**
- R13. Money `$ 2,816.40` (symbol + NBSP + 2dp, currency always shown); date `3 June 2026`; time `14:38`; ranges `07:30 – 19:00`; IDs mono zero-padded; every changing number `tabular-nums`; numeric/time content **`font-mono`**, right-aligned.

**States and motion (11-campus-states)**
- R14. Every table/list ships a row-mirroring skeleton with header, never a spinner or "Loading…"; `LoadError` scoped to the segment that failed, with retry; `SaveError` on writes; `SavingOverlay` around what is being written.
- R15. Refusals name who can (`whoCan`); a verb the person cannot use is **disabled with the reason, not hidden**.

**Accessibility (05-rules)**
- R16. Every control labelled; icon-only buttons `aria-label`; focus-visible ring; overlays trap and return focus; roving tabindex in composite widgets; 36px targets (44px mobile-primary); never colour alone.

**Phone (playbook "Phone Rules", SPEC "Mobile-first 390px")**
- R17. First screen belongs to the records, not the chrome. Stat tiles two-up. Never the same fact twice in one band. Rows: two lines, one fact on the right, money carries its currency. Pickers are sheets on a phone. Strips scroll to the edge and snap; labels never wrap. Table → cards below `md`.

**Dashboards (08-cookbook)**
- R18. StatHero → KpiGrid → RowCard drill targets → EmptyState. Every number links to where the work is done; missing baseline renders `—` not `0%`; `h2` label wraps the value.

**Workflow (playbook "Workflow Action Rules", screen contract "CRUD is not optional")**
- R19. Render only valid next actions; show requirement context ("To continue, complete…"). List-to-detail preserves tab/search/filter/sort/page. Every listed entity has create/edit/delete reachable.

## 1. Information architecture and navigation

### 1.1 Two nav definitions that disagree, and the sidebar is the worse one
- `lib/navigation.ts:280-398` defines the schools section as **11 bands / 41 items** (Students, Attendance, Academics, Teaching, Results, Boarding, Fees, People, Communication, Services, Reports and documents), alphabetical within band, `flattenGroups: true`.
- `lib/workspaces.ts:363-484` (`WORKSPACE_PROFILE_RECIPES.SCHOOLS`) defines **17 sections** with a hand-picked subset of refs. `buildProfileSections` (`lib/workspaces.ts:713-745`) resolves each ref against the nav item and **drops refs that are not nav items**, and a single-ref section renders as a plain link carrying the *item's* label.
- The screenshots (`the-roll/01-overview.png` and every other one) show the `workspaces.ts` version is what ships. Consequences:
  - **"Whole school" is a top-level sidebar entry** (`workspaces.ts:397-400` → item label at `navigation.ts:316`). Out of its "Attendance" band the label means nothing. Registrars will not find attendance. **P0 IA bug.**
  - The "Academic setup" section (`workspaces.ts:410-419`) refs `/schools/academics`, `/schools/classes`, `/schools/subjects`, `/schools/academics/syllabus`, `/schools/academics/identity`. None of the first three and last are nav items (they are redirect stubs), so the section collapses to the one survivor, **"Scheme of work"** — which `app/schools/academics/syllabus/page.tsx:504` redirects to **`/portal/teacher/syllabus`**. An administrator clicking the only academic-setup entry in their sidebar lands in the teacher portal. **P0.**
  - Years/terms, classes/streams, subjects, the school day, grading and identity — the entire master-data ladder a school admin sets up first — are **not in the school sidebar at all**; they live under Management → Master Data with a second rail (`records-desktop/01-subjects-list.png` shows the double nav). `navigation.ts:318-341` added "Academic setup", "Identity and records", "Rooms" reach-across links, but `workspaces.ts` never picked them up.
- **Orphan routes** (reachable, working, absent from the shipped sidebar): `/schools/calendar`, `/schools/attendance/follow-up`, `/schools/staff`, `/schools/teachers/assignments`, `/schools/teaching/lessons`, `/schools/teaching/resources`, `/schools/messages`, `/schools/boarding/hostels`, `/schools/boarding/allocations`, `/schools/boarding/leave`, `/schools/library/loans`, `/schools/finance/arrears`, `/schools/finance/ledger?view=receipts|refunds|waivers|credits` (only "Ledger and structures" is linked), `/schools/results/publish/windows`, all six `/management/master-data/schools/*` pages, `/schools/documents` (present) — 16 destinations. Absence follow-up, Messages and Library loans are daily-office screens.

### 1.3 Duplicated and redirected routes
- `app/schools/fees/page.tsx` → `/schools/finance`; `finance/invoices|receipts|refunds|waivers/page.tsx` → `ledger?view=`; `academics`, `academics/identity`, `classes`, `classes/[id]`, `subjects`, `subjects/[id]`, `results/publish/windows` → `/management/master-data/schools/*`; `academics/syllabus` → teacher portal; `portal/*` → `/portal/*`. Fourteen of 69 page files are redirect stubs. Harmless individually, but they are what the `workspaces.ts` refs point at, which is why the sidebar loses them.
- **Publishing windows are CRUD'd in two places**: `components/schools/results/publishing-content.tsx:406,474` ("Publish windows", `New publish window`) and `components/schools/academics/grading-content.tsx:527,635` ("Publishing windows", `New publishing window`). Different copy, different shells, same table.
- **Subjects are CRUD'd in two places**: `schools-teachers-content.tsx:716,860-872` (Subjects tab, "Add Subject") and `schools-subjects-content.tsx` (master data, "New subject"). Assignments likewise: teachers tab vs `/schools/teachers/assignments`.
- **Result sheets are listed four times**: `results-overview-content.tsx`, `mark-sheets-content.tsx`, `moderation-queue-content.tsx` ("All sheets" tab, :314), `publishing-content.tsx` ("All sheets" tab, :408). Same rows, four filter rows, four skeletons.
- **Arrears/ageing exists three times** with inconsistent numbers on screen: `fees-grade-picker.tsx:401` (Ageing: "Over 90 days $ 3,920.00"), `reports-arrears-content.tsx` / `schools-reports-enhanced-content.tsx:1105` (chart shows the bar in **61–90**, chip "90+ days 0"), and the dashboard's aging sparkbars (`schools-dashboard-content.tsx:1212-1216`). A bursar cannot tell which is right.
- `/schools/teachers` (teaching staff, own profile table) vs `/schools/staff` (support staff = HR employees) vs `/people` — three staff lists, two data models, and "Find the employee" on every teacher row (`teacher-hr-desktop/01-teacher-hr.png`) because the two are not joined.

### 1.4 Vocabulary drift across modules
- Class / year group / stream: master data calls the ladder "Classes and Streams"; students table has **Class = stream** and **Year = class** (`students-list-content.tsx:358-364`), while every `ClassFilter` is labelled "Year group" and class-scoped pages are titled "Year group" in the app bar. `the-roll/02-students.png` shows "CLASS —" beside "YEAR Form 1" under a group header "Form 1" — three columns saying one thing and one of them blank.
- Admissions/Applications/Enrolments/Enrollment (`admissions-board-content.tsx:266-267` "Enrolments" tab; `schools-reports-enhanced-content.tsx:849` "Enrollment"; `schools-admissions-content.tsx:199` "Enrollments").
- Ageing (`fees-grade-picker.tsx:401`) vs Aging (`schools-reports-enhanced-content.tsx:848,1105,1162`).
- Results / marks / mark sheets / result sheets / assessments (`components/schools/assessments/*` vs `results/*`; nav "Result sheets", h1 "Results overview", button "New mark sheet", page "Form 1 marks").
- Notice / reminder / nudge / "send it home" — four verbs for the same `POST /api/v2/schools/notices`.

### 1.5 The sidebar is identical for every persona
`lib/auth-core/role-routes.ts:22-24` restricts only `SALES_REP`. No school persona is route-gated, `preferredHomeHref` is `/schools` for all (`workspaces.ts:364`), and `workspaces.ts` sections are static. So a BURSAR sees Boarding, Results, Homework and Scheme of work; a WARDEN sees Fees. The comment at `workspaces.ts:367-370` ("the registrar opens Students, the bursar opens Fees") describes an intent the code does not implement.

### 1.6 Proposed restructure
1. **Make `navigation.ts` the single source** — delete the SCHOOLS `sections` array in `workspaces.ts` (or generate it from the nav bands) so the 11 bands render as the sidebar with `flattenGroups`. This alone restores the 16 orphans and kills "Whole school".
2. **Bands, renamed for the person who owns them** (order = the school day): Overview · **Roll** (Students, Applications, Guardians, Roll up the year, Import) · **Attendance** (Registers, Absence follow-up) · **Boarding** (Bed board, Hostels, Allocations, Leave, Welfare) · **Teaching** (Timetable, Homework, Lesson plans, Resources, Targets, Scheme of work→*only if the office needs it, else drop*) · **Results** (Sheets, Moderation, Publishing) · **Fees** (Overview, Ledger[Invoices|Receipts|Credits|Refunds|Waivers|Structures], Arrears) · **People** (Teachers, Support staff, Assignments) · **Communication** (Messages, Notices, Parent meetings) · **Services** (Library, Loans, Transport) · **Setup** (Years & terms, Calendar, Classes & streams, Subjects, School day & rooms, Grading & publishing windows, Records & identity) · **Reports & documents**.
3. **Persona-aware rail and landing** via `schoolAccess(role).actionsOn(resource)`: hide bands where the persona has no `view` grant at all (WARDEN has none on fees/results); order the persona's own band first; `preferredHomeHref` = `/schools/finance` for BURSAR, `/schools/students` for REGISTRAR, `/schools/results/moderation` for HOD, `/schools/boarding` for WARDEN. Keep verbs disabled-with-reason inside a page (rule R15) — that rule is about verbs, not about showing a warden a fee ledger.
4. **Collapse the duplicates**: one Publishing-windows surface (Setup › Grading), one Subjects surface (Setup), one Sheets list with the workflow tabs as views (Overview chips → Sheets [Entering | In review | Sent back | Ready | Published]), one Arrears surface (Fees › Arrears) that the finance overview and dashboard link to rather than re-draw.
5. Bring master data into the school shell (`MasterDataShell` under `/schools/setup/*`) or at minimum give the management pages a "Back to School Operations" and the school's own sidebar — the double rail in `records-desktop/01-subjects-list.png` is four levels of navigation before the table.
6. Name each screen once: app bar title = nav label = the thing the page is (drop `PageHeading` from the 20 pages listed in §2–4).

### Detailed notes and suggested edits (ADMIN)

**A1. Master-data shell double navigation (P1).** `records-desktop/01-subjects-list.png`: school sidebar (left) + Settings/Master Data rail (second column) + description line + band + tabs + stacked filters + control row before the first row at y≈440. Move the six school master-data pages under `/schools/setup/*` inside the school shell, register the title with `PageChrome`, drop `description`. Where that is not possible now, at least pass `description={undefined}` in `app/management/master-data/schools/*/page.tsx:313-466` and let the band carry state.

**A2. Filters stacked, primary floating (P1).** `schools-classes-content.tsx:405-430`, `schools-subjects-content.tsx:298-336`, `school-day-content.tsx:408-440`, `grading-content.tsx:598-636`: the `FilterBar` and `CreateButton` are siblings in a flex-wrap that breaks into three rows at 1440px. Wrap in `TableControls` (`filters=` + `actions=`) and move the create verb into `PageChrome`. Remove the DataTable's internal search (`searchBehavior`) on these screens so there is one search (R4).

**A3. Band chips repeating tab counts (P1).** `schools-classes-content.tsx:369-372` vs `:398-399`; same on students (`students-list-content.tsx:511-515` vs `:548-552`), results overview, fee ledger. The band should carry what the tabs cannot — "On the roll 120", "Unstreamed 6" — not the tab totals.

**A4. Teachers page Actions column clipped (P1).** `the-roll/04-teachers.png`, `teacher-hr-desktop/01-teacher-hr.png`: TEACHER (avatar + name + `TCH-008 / email` mono), DEPARTMENT, PROFILE FLAGS, ASSIGNMENTS, HR RECORD (badge + button), ACTIVE, ACTIO… The HR-record button is the widest thing in the row and identical on every row. Fold it: HR RECORD becomes a badge that is the link; "Find the employee" moves into the row menu; or add a band action "Link 8 teachers to HR".
