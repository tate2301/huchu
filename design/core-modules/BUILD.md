# Building a screen: the brief for each piece of work

Read this, the rows of `spec/routes.md` you were given, and the outlines of their boards. Nothing else up front. Open other files only when a step needs them.

## The rule

The design is the app. Every board in your rows becomes a working route with real data, at the route the board names.

Where the app already does something the board never drew, keep it:
- Port its screen onto the kit (same components, same page shape as the boards).
- Link it from the module's panel or from the new page.
- Forward its old address to the new one with `redirect()` in the old `page.tsx`, so bookmarks still work.

Nothing that works today may be lost.

Don't redesign, reword or add features. When the board and the app's data disagree, build what the data allows and write one line in `NOTES.md` under the module (newest first).

## Read the board, cheaply

```
python3 -I design/core-modules/tools/check/outline.py <Board>        # the board as a tree, shell skipped
```

- The board's own HTML is `design/core-modules/boards/view/<Board>.html`. Open it only for a detail the outline leaves out.
- For sizes and gaps, grep `design/core-modules/boards/assets/core.css` for the class.

## Where things are

| Need | Use |
|---|---|
| Kit components | `@/components/core`: Button, ButtonLink, ButtonGroup, Kbd, Field, Input, Select, Switch, Check, Status, Pill, Count, Meter, Finding, GroupHead, FormSection, Setting, Empty, Banner, FigureStrip, Kpi, Tabs, Segmented, TableShell, TableFoot, SelectCell, useSelection, Drawer, Icon, VaneMark, useShortcut |
| Kit CSS | `components/core/kit.css` is generated by `design/core-modules/build/build-kit-css.mjs`. Change the generator, never the output. Page classes from the boards (`.tools`, `.finding`, `.table`, `.status`…) are in it, scoped under `.ck` |
| Page frame | `PageChrome` (`@/components/layout/page-chrome`) sets the top bar's title and primary button. Wrap the body in `KitScreen` (see `components/books/figures.tsx` → `BooksPage`) |
| Module panel | `lib/navigation.ts`: the module's `items`. Groups, counts and saved views follow the board's panel |
| A finished example | Books → Invoices: `app/books/invoices/page.tsx` (page, query, mutations, states), `components/books/invoices-view.tsx` (pure view), `app/api/books/invoices/route.ts`, `lib/books/invoices.ts` (reads and shapes the data, tested) |
| API routes | `validateSession`, `successResponse`, `errorResponse` from `@/lib/api-utils`. Always scope by `session.user.companyId` |
| Fetching | `@tanstack/react-query` with `fetchJson` from `@/lib/api-client`; toasts from `@/components/ui/use-toast` |
| Ported registers | `components/management/ui/*` (fact lists, column list, activity trail) already take the kit's measures |

The split is always the same: `lib/<module>/*.ts` reads and shapes the data (pure where it can be, with a `*.test.ts`), the API route serves it, a pure view renders it, and the page wires them together.

## States

Each route needs:
- **Loading:** a skeleton in the page's shape.
- **Empty:** the kit's `Empty`, saying what to do next.
- **Error:** what failed, plus Try again.
- **No permission:** say who can do it.

Long names truncate in their cell.

## Words and rules

- British English, sentence case, the words in `design/core-modules/app/lexicon.json`.
- Every primary button shows its shortcut, and the shortcut works (`useShortcut`; the shortcut is listed in `spec/shortcuts.md`).
- **Vane:**
  - The helper is always called Vane, never AI, assistant or Claude, and never shown with a sparkle.
  - Vane drafts. A person presses the button that sends, pays or saves, and the server enforces that.
- **Data changes:**
  - A new table, column, role or API that changes data is proposed first, with its migration, and you stop there. Report it as "needs approval" and carry on with the rest.
  - New tables get the lines from `pnpm vane:reader-sql`.

## Check before you commit

The dev server runs on port 3100, and workspaces live on subdomains. The sign-in state file is given in your task.

```
node design/core-modules/tools/check/designcheck.mjs <Board> http://floorcode.apps.pagka.local:3100/<route> \
  --state <state.json> --390 --shot <scratch>/<Board>.png
```

1. **Score.**
   - The score must be 95% or more.
   - Each missing item is either fixed or explained in NOTES.md (real data, an item the app has no source for).
   - Panel items from other modules and the selection footer the board draws pre-selected are known noise.
2. **Layout.** The 1440 and 390 checks must be clean.
3. **Look once.** Open the side-by-side PNG and fix anything visibly off: alignment, spacing, a wrong component.
4. **Code checks.**
   - `pnpm typecheck 2>&1 | grep -E "error" | head`, which must be empty.
   - `pnpm exec eslint <changed files>`.
   - `pnpm exec vitest run <module paths> 2>&1 | tail -5` (never `pnpm test -- …`: it runs the whole suite, eleven minutes).
5. **Commit** each workflow with a message saying what a person can now do. End it with the trailers given in your task.

Don't push.

## What to report back (ten lines at most)
